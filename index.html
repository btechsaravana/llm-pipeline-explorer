How a question becomes an answer from your own data

Three paths, one live example. Click any stage to open it and play with the real parameters. The running example is a small set of e-Sevai invoices and the question “How much did Murugan e-Sevai pay in March?”. You can change the question in stage C1.

Text version of the steps

How the paths connect: A’s trained model is what runs in C8–C9. B’s vectors and index are what C3–C5 search. C is the only path that runs when a user asks something.

How this page simulates things. Retrieval maths (cosine, BM25, hybrid weights, filters, KV-cache and FLOP sums) is computed live. The embedding is a toy 8-number vector with named dimensions so you can see what is happening, where real models use 384–3,072 unnamed numbers. The cross-encoder, attention weights, loss curve and the final answer are small rule-based stand-ins for real models.
